# V0.8 固定协议历史滚动评估

## 状态与边界

本指南描述实现与可复现协议。真实训练报告 ID、实际指标、数据库前后内容保护和浏览器验收尚待记录；不能把合成测试通过当作真实评估完成，也不承诺模型优于零收益基线。

仅支持 `000001.SZ`；历史范围固定为 `2022-01-04` 至 `2026-09-30`。这段历史此前已经观察过，所以 `evaluation_kind=retrospective_walk_forward`、`history_previously_observed=true`、`prospective_validation=false`。它不是干净留出集、实时预测或投资建议。价格未复权；估值并非已证明 point-in-time 的数据，供应商后续修订也不在本次证明范围内。

## 代码阅读顺序

以下目录均相对仓库根目录；先阅读协议，再看执行、持久化和展示。

1. `StockAnalysisSystem/python-services/stock-analysis-app/analysis/evaluation/protocol.py`：原始交易日边界与 purge；因果特征见相邻 `analysis/forecast/samples.py`。
2. 同目录 `training.py`：三个方法与六次拟合。
3. 同目录 `contracts.py`：报告、摘要、有限数与严格字段合同。
4. 同目录 `reports.py` → `repository.py`：不可变报告先落盘，摘要随后追加数据库。
5. `StockAnalysisSystem/python-services/stock-analysis-app/api/evaluations.py`：只读列表和详情。
6. `StockAnalysisSystem/frontend/src/utils/evaluation.js` → `src/api/analysis.js` → `src/views/analysis/AnalysisEvaluationLive.vue`：验证 DTO、请求隔离、四条曲线和指标展示。
7. `StockAnalysisSystem/scripts/verify_v08_evaluation.py` 与 `scripts/tests/test_verify_v08_evaluation.py`：独立 Decimal/calendar 核对，不导入生产评估或训练。

## 固定协议与单位

协议 ID 为 `v08_expanding_3x100_1`。原始 N 日中最后一个日线只提供最后目标收盘价；信号取零起始索引 N−301 至 N−2，连续三窗各100点，共300点。所有方法使用完全相同日期。训练集合逐窗扩张，标签日期必须严格早于该窗第一个信号日期；紧邻信号的一条训练候选被清除。每窗至少300个训练样本，warmup 不得重新移动评估边界。必须提供完整、显式可信交易所日历；不能用工作日猜测、填补缺日或自动补采。

固定23特征与 `v07_fixed_1` 保持不变。`zero_return` 的预测恒为0；Ridge 为 alpha=1、solver=svd，缺失值采用仅在该窗训练数据拟合的中位数（全缺失列为0）及训练专用 scaler；XGBoost 使用 V0.7 固定参数、单线程，无 eval_set、早停、搜索或按成绩重跑。总计六次模型拟合；不会替换 V0.7 生产模型。

`actual_return=close[t+1]/close[t]-1`，`horizon=1`，`target=next_trading_day_close_return`，`units=fractional_return`。例如0.01表示1%；DTO 保留小数收益，仅展示时转换一次。RMSE/MAE 同为小数收益单位；R² 无量纲且可以为负，实际收益恒定时为 null。总指标用300行重新计算，绝不能平均各窗 RMSE 或 R²。

## 单行命令

日历是用户提供的可信本地 `tushare.trade_cal` JSON，包含 source、exchange、start、end、open_dates；不要提交日历、模型、报告或私有环境文件。以下训练命令从 `StockAnalysisSystem/python-services/stock-analysis-app` 执行；只在源数据和日历范围已确认后运行一次。

```powershell
D:/Python/python.exe -m scripts.evaluate --stock 000001.SZ --start 2022-01-04 --end 2026-09-30 --calendar ../../../.tmp/v07-authoritative-calendar.json
```

将 stdout 的完整 `eval_<32小写hex>` 作为报告 ID。以下只读核对命令从仓库根目录执行；把占位符替换为真实 ID。

```powershell
D:/Python/python.exe StockAnalysisSystem/scripts/verify_v08_evaluation.py --stock 000001.SZ --report <真实eval_ID> --start 2022-01-04 --end 2026-09-30 --calendar .tmp/v07-authoritative-calendar.json --api-base http://127.0.0.1:8084 --timeout 15
```

离线合成核对测试不依赖运行中的数据库或 API，也不会训练或发布。


## 完整性与故障处理

报告保存为 app 的 `reports/v08/eval_<ID>/report.json`，上限2MiB。摘要使用新 `analysis_type=v08_walk_forward_evaluation`，UTF-8 长度不超过65535字节，prediction/confidence 均为 NULL；不改表、不更新或删除旧记录。列表只显示成功追加的摘要，数据库失败留下的孤立文件不能自动列出。详情必须核对路径安全、SHA-256、字节数、stock、report ID 和完整摘要投影；拒绝符号链接、越界、重复 JSON 键及非有限数。

只读 API 是 `GET /api/analysis/evaluations?ts_code=000001.SZ&limit=20` 和 `GET /api/analysis/evaluations/000001.SZ/<真实eval_ID>`。列表最多100条，详情必须完整300点。503先检查本项目8084健康、数据库连接和摘要对应报告文件是否存在且完整；不要回填模拟报告或重新训练“修好”指标。数据库写失败需要保留孤立文件与错误证据；不自动删除或绕过摘要发布。API 不通过 GET 触发训练。

独立核对器仅 SELECT 原始 date/close 与 GET 详情，超时必须有限且小于30秒，所有 JSON 有界读取≤2MiB；错误输出脱敏且退出1。PASS 证明300个相邻可信开市日标签、实际收益、固定窗与严格清除范围、真零基线、每窗和总指标算术一致。它不证明 estimator 实际如何 fit、训练中位数拟合来源、全部 OHLC/估值数据 hash、报告文件 hash（由服务持久化层验证）、供应商历史可获得性或收益优势。

真实验收还应记录原始日线/daily_basic 和 V0.7 记录前后有序内容 hash 不变、新摘要仅追加一条、V0.7 API 可读，以及真实浏览器浅深主题、390px、快速报告/stock切换、无报告与接口故障无旧数据残留。没有这些证据时，应明确标注未验收。
