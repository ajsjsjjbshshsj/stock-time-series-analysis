# 特征启用与夜间预测

此链路把数据准备、特征版本和模型操作分开。特征构建成功不代表已启用；启用成功不代表已训练模型；预测成功不代表已发布或保证收益。

## 1. 显式迁移

先停止训练 worker，确认执行槽空闲，在 `python-services/stock-analysis-app` 使用已配置环境运行单行命令：

```powershell
python scripts/training_worker.py migrate-automation
```

只创建四张控制元数据表：`analysis_feature_activation`（切换意图）、`analysis_daily_plan`（默认关闭的计划）、`analysis_daily_cycle`（全局日期特征链）、`analysis_daily_run`（每模型每日预测状态）。不修改行情、不训练、不启用计划。已有 auth、training、workflow、collector 和 feature-store 迁移仍须先完成。

## 2. 手动特征与模型操作

管理员在数据准备任务完成后提交“特征暂存”。成功后进入任务详情，显式选择“核验并启用特征”；回滚只允许已有 READY 归档版本。完整来源/特征校验在独立 worker 执行，HTTP 只绑定小型元数据和封存摘要。

所有构建、启用和模型任务共用单执行槽。启用排队时可取消，进入 RUNNING 后不允许取消，因为 MySQL 表切换不能承诺撤销已经发生的 DDL。切换持有数据库命名锁，旧版本归档保留，不覆盖旧模型或信号。

启用完成后“进入模型工作台”会带入真实特征 build id。管理员仍需显式提交训练、预测或回测。版本若变化，任务绑定拒绝漂移，不悄悄改用新版本。旧模型的算法、池成员、历史前缀和日期兼容性校验仍生效；不兼容需管理员处理，不会自动重训。

## 3. 夜间计划

模型工作台的“每晚预测”选择已保存模型，创建后默认关闭。仅创建者管理员能启用/关闭；所有管理员能查看。启用前请确认内存、磁盘、worker 和采集夜间调度可持续运行。

训练 worker 每次空闲轮询时检查计划，仅处理可信交易日历中**当日北京时间20:00及以后**的 session。必须存在相应当日20:00全市场 SH/SZ A 采集成功证明：缺口与冲突均为0、批次封存有效、无筛选股票池。16:01股票池准备任务、历史补采、周末或过期日历不能冒充当晚完成。

同日多个计划共享一次全局特征构建和启用；各模型独立预测。持久化日身份、阶段子任务及稳定幂等键用于进程重启、响应丢失或重复轮询。依赖未就绪至少等待60秒；边界/角色变化和失败子任务显示 BLOCKED。不会自动补跑旧日期。

采集完成证明沿用缺口采集器的真实格式：`conflicts` 是冲突记录列表，必须为空（兼容历史整数0）；`unresolved_keys` 必须是整数0。非空冲突、布尔值或浮点数0不能冒充通过，不改写已封存采集结果来适配分析端。

结果通过既有模型工作流保存为**未公开发布**。用户选择已审核上线的保存模型及兼容股票池时，用户预测接口会核对日期、模型、数据/特征版本及完整输入摘要；完全匹配才复用该封存结果，并给当前请求用户建立访问授权。它不需要逐条结果公开发布，也不会把私有结果无条件推送给所有人。旧“已发布结果”列表仍须管理员另行发布。计划中没有 train、import 或 publish 操作。关闭计划阻止后续阶段，但不撤销已经入队的任务，需单独取消；运行中的特征切换不可取消。

### Windows 持久启动

在项目 `.env` 配置 `NIGHTLY_UPDATE_AT=20:00` 和明确的 `NIGHTLY_BOOTSTRAP_START`（最近已存行情的次日，例如数据库截至2026-10-13时填写2026-10-14）。更新起点同时限制夜间规划和市场队列执行/恢复，旧日期任务保留，不因启动夜间服务而重跑。未指定起点的原CLI行为不变；普通历史补采仍可显式运行。

从项目 `StockAnalysisSystem` 目录先检查配置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/runtime/start_nightly_services.ps1 -PythonExecutable python -CheckOnly
```

需要 Python 位于 PATH，或将 `-PythonExecutable` 指定为本机解释器。首次部署确认其他电脑没有采集worker，随后通过 WMI 或 Windows 任务计划程序运行同一入口。加 `-RegisterTask` 显式登记当前用户的每天北京时间20:00和登录恢复触发器；不存储账户密码，不注册系统级账户。当前用户必须已登录且电脑保持开机，休眠/关机期间不执行；恢复后只补实际缺口。任务名为 `StockAnalysis-Nightly`，不覆盖属于其他入口的同名任务。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/runtime/start_nightly_services.ps1 -PythonExecutable python -RegisterTask
```

入口只保持唯一采集worker和唯一分析worker，不启动训练、不代替管理员启用模型计划，也不代替API/数据库启动。采集仍使用根锁、Tushare原限流、重试截止时间与停牌证据；不删除锁绕过占用。已有采集进程若范围或夜间参数不同，会拒绝启动并要求先安全停止。日志在 `logs/runtime/nightly-*.log`，不把凭据写入任务参数。

### 日期、失败和验收

20:00前或非交易日不会提前创建当天预测。采集尚未完整成功时计划等待；失败特征/不兼容模型明确阻塞，不训练替代模型、不假装成功。重启沿用日期身份、稳定幂等键及阶段任务，不重复计算；已有成功夜间结果仍需完全匹配当前用户请求的输入绑定才能复用。当天未跑完的链路不会在次日冒充当天最新预测。

设置夜间更新起点后，分析worker每分钟从采集端的**已封存交易日历缓存**校验并合并新日期，不在分析端调用数据源，也不按周一至周五猜测交易日。仅在执行槽未隔离、空闲且没有已入队模型/特征任务时原子更新 `TRAINING_CALENDAR_FILE`（默认 `.runtime/training_tasks/calendar.json`）；原文件按内容摘要备份到同级 `calendar_history/`。日历缺日、历史开闭市冲突或来源摘要损坏时保留原文件并显示依赖未就绪，不能为了继续预测绕过。采集缓存未覆盖当天时等待采集端刷新；这不是“今日采集完成”的证明。

## 4. 中断恢复

切换前写入不可变 PREPARED 意图，确认当前活跃版本且核对物理表身份后才执行 RENAME。只有确认已启用的目标，才记为 COMMITTED；已恢复旧表则记为 ABORTED。不能判断的状态保持执行槽隔离，不允许模型读取错误版本。

确认原机器 worker 和全部后代进程停止后，使用既有 `training_worker.py recover` 的**完整 STOPPED 确认串**和管理员身份恢复执行槽。恢复不会重排中断任务。再显式提交相同候选的启用/回滚，受控恢复只处理已记录、完全匹配的表身份；未知表或其他候选意图拒绝操作，不删除表。

## 验收边界

自动化代码和隔离测试不等于生产全市场构建、真实跨夜持续运行或远程部署已验收。旧模型文件保持不动；无服务器时远程安全验收待部署。普通用户不能训练，只能通过已上线模型的受限预测接口访问自己的封存结果，或读取旧公开发布列表。
