# 三模型工作流：训练、使用与发布

日常启动、登录、已有结果查看、发布与撤回，见 [本机结果使用速查](LOCAL_RESULTS_QUICKSTART.md)。

本功能不要求策略盈利。`COMPLETE` 表示结果计算及完整性校验成功，不表示策略有效；负收益、低 RankIC 或未定义的相关系数都应如实呈现。`NOT_READY` 表示执行证据不足，不生成虚假净值，也不可发布该回测；独立预测结果仍可审核发布。

## 使用顺序

1. 使用管理员账户登录，打开 `/#/models`（模型工作台）。普通用户在 `/#/user` 查看已发布结果，或选择兼容股票池和已保存模型请求预测；不能训练、采集、修改参数或发布结果。
2. 选择“训练模型”，确认已入库数据的真实起止日期，选择算法和受限参数后提交。界面“已入队”不等于已训练，关闭页面不停止任务。
3. 完成后刷新“已保存模型”，查看特征数、参数、实际训练轮数、设备与模型已见数据边界。用指定版本提交预测或回测，不能替换它的股票池、scaler 或特征顺序。
4. 在结果列表预览排行、单股记录、权益分页、交易、未成交说明和成本假设。预测仅有模型分数，不生成虚拟收益曲线。历史研究与模型选择后的样本分别标注，后者也不等于保证有效的前瞻检验。
5. 管理员明确点击“确认发布给用户”。发布的是 `result_id`，不是自动发布模型。重新训练/计算产生新版本，旧模型和旧封存包不覆盖。撤回后用户端后续请求返回不可见；已经下载到浏览器的数据无法追溯收回。

保留的 `/#/training` 是旧工程验证入口，不会替代新工作流；两者共享同一持久化队列与执行槽。旧 Transformer signals 端点与历史封存结果保持不变。

## 算法与单位

| 算法 | 训练范围与参数 | 输出 / 执行语义 |
| --- | --- | --- |
| XGBoost | 单只沪深股票，1–100棵树、深度1–6 | 下一交易日上涨概率；概率≥0.5才作为研究买入信号，持有1交易日 |
| LightGBM | 固定沪深A股全市场；原收益或日截面排名，1–300轮，RMSE/RankIC早停，训练期探针 | 原收益或中心化排名分数，二者不能混称概率；持有5交易日 |
| Transformer | 显式冻结10–20只股票，默认20只、1 epoch、batch1，上限5 epoch/batch2，保留探针 | 复用原特征/scaler/股票映射；标签 `open_T5/open_T1-1`，标签偏移5但实际持有4交易日 |

Transformer 原始数据集要求至少10只股票，此入口不是全市场GPU训练入口。GPU可用时使用CUDA并限制单进程显存预算（至多约4GiB且不超过设备80%），记录实际设备与峰值。探针和部分预处理仍使用CPU。A100大规模配置需后续明确扩容。

默认20只建议池仅按可信源清单的完整起止日期和交易日行数筛选，不按收益挑选；显式提交后池不再改变。当前 Transformer 小池输入沿用严格会话覆盖要求，有已知停牌/退市缺口不代表行情造假，但该配置可能被拒绝，不能自动填充或静默移除成员。LightGBM 的固定全市场管线则按上市、停牌等证据逐日统计样本资格，不要求补成全股票×全交易日网格。

三者都保存原生模型并重加载验证；HTTP 请求不加载 torch，不推理，不回测。推理读取未成熟标签的最新特征，使用固定训练 scaler；保留完整原始依赖历史计算路径依赖指标。数据库后续扩展时，新模型核对冻结历史前缀；历史价格或算法依赖改变需明确重训，不自动改写模型。

LightGBM 使用磁盘矩阵；全市场数据逐股读取。预测逐股/小池执行，只有回测账本汇总所需分数与价格。默认全市场资源预检：可用内存≥8GiB、临时盘≥16GiB；子进程树≤6GiB、最多180分钟、盘剩余≥2GiB。不足时不静默缩池。夜间协调器在创建任务前检查资源，不足则记录等待状态、60秒后再检查；已创建任务的失败处理见下文。行情稀疏由上市日期、已证实停牌等解释，不能补造价格。

实际执行时限由 `tasks.resources.MAX_EXECUTION_SECONDS` 统一控制（10800 秒），执行监督与候选产物耗时验收使用相同上限。已封存的 `bounded_v1` 训练配置保留原值，避免仅修改运行时限就使旧模型的算法哈希失效。时限调整需在 worker 安全空闲时重启后生效，不中断或追溯修改正在运行的任务。夜间流程仅对 `FAILED/RESOURCE_UNAVAILABLE` 且无候选产物、无候选目录、无激活意图的任务，按阶段最多创建两次额外尝试，间隔至少60秒；重试记录持久化，原失败任务不改写。中断、取消、部分产物、来源校验失败和运行中超限均不自动重跑。

特征快照读取先取得股票代码清单，再按每组最多64只股票执行有序关联查询，组内使用服务端流式游标、每批1000行；应用只缓存当前股票历史及读取缓冲区，不装入全市场面板。这样减少逐股查询，也避免把整个市场一次排序。此流式读取仅供快照写入使用，消费期间不能在同一连接执行其他SQL；发布、回滚及对账校验继续逐股读取并在返回该股数据前关闭游标，以便在同一只读快照事务中交错查询特征表。单股及全局来源哈希共享一次逐行规范编码，字节格式、精度、空值和全部校验保持不变；提前关闭、异常退出时先释放读取结果，再回滚只读快照事务。

新的特征构建封存 `performance.json`，记录 `source_snapshot`（数据库读取、Parquet写入和来源摘要的组合耗时）、`snapshot_verification`、`source_shard_read`、`feature_compute`、`feature_materialize`、`feature_persist`、`output_hash`、`metadata_persist` 与 `artifact_inventory` 的累计秒数和调用次数。最终 `artifact_verification` 耗时通过项目日志记录，避免为补写计时而修改已封存文件。计时不属于特征值或模型训练配置，原有特征版本及模型不会因此自动被覆盖或重训。

此优化不等于增量特征构建或跨任务断点续跑，也不跳过历史、停牌或生命周期校验。实际全市场耗时需重新验收，不能把小样本基准直接当作整条链路的提速倍数。

本机账本尚非无限长的流式账本：提交回测前，以固定股票数×已完成交易日数（含执行尾部）预检，最多250,000个价格观测；运行时再次逐股累计限制，且只保留区间内7列价格，不保留特征或历史前缀。全市场需选较短区间，长达多年的全市场回测明确拒绝，不等到OOM后缩池重试。扩容/流式账本是后续工作。

服务器以可信交易日历和上海时间判定已完成交易日：严格16:00之后才可使用当日，否则前一已完成交易日；休市顺延。UI来源上限与后台信号/执行尾部均受此限制，不以库中已出现某日记录作为收盘证据。

生产 API 的认证与旧预测查询保留5秒数据库读写预算；任务/模型控制面使用独立连接，单次数据库读取最多30秒、写入10秒，连接与连接池等待仍为5秒，连接在应用退出或启动失败时释放。外部注入的服务/连接仍遵循调用方配置和所有权。全市场来源身份校验可能超过一分钟，网页对用户预测、模型工作流及全市场工程任务的创建请求最多等待180秒；登录等普通请求仍为10秒。这些是入队前校验预算，不是 worker 的180分钟执行时限，也不会把推理或训练放进 HTTP 请求中。预测依赖503提示数据/封存/连接故障，不误报成认证初始化失败。

## 用户选择股票池与模型

用户预测优先复用同一模型、股票池及数据版本的已有结果；缺少结果时提交受控的保存模型推理任务，不重新训练。HTTP 请求只读状态或入队，实际计算由独立 worker 执行。结果可直接在用户端显示，与管理员审核发布研究结果是两条入口。

可选池来自已保存的固定快照，不表示任意池可配任意模型。全市场 LightGBM 可服务其冻结成员内的完整指数或行业池；必须先验证全部成员兼容，不能偷偷取交集。Transformer 小池和单股 XGBoost 仍受原冻结范围约束。展示指数快照真实来源日期，不能把最近一次成分记录标成今日成分。缩小展示池不重新编号、不重训，也不把模型分数改称收益或概率。

启用夜间计划后，采集完成证明、特征构建、激活和保存模型预测依次推进，多个模型共享当天特征周期。启用 `NIGHTLY_BOOTSTRAP_START` 时，空闲 worker 从已封存采集日历缓存滚动扩展运行日历；有排队/运行任务时不切换，已有交易日冲突或证明缺失时拒绝更新，不猜测工作日。原日历按哈希留档。进程必须持续运行；安装源码不等于夜间调度已启动，也不等于已经通过跨日或故障验收。

## 首次部署与迁移

在项目根的 `StockAnalysisSystem/.env` 配置现有数据库、protected登录、可信来源/日历；密钥用真实值，不写 `${VAR}` 嵌套占位符。以下命令工作目录为 `StockAnalysisSystem/python-services/stock-analysis-app`，Python使用本机已配置环境：

```text
python scripts/training_worker.py status
python scripts/training_worker.py migrate-workflows
python -m uvicorn api.forecast:app --host 127.0.0.1 --port 8084 --no-proxy-headers
python scripts/training_worker.py run
```

迁移前暂停新提交、确认执行槽空闲并停止旧worker，再显式执行 `migrate-workflows`，重启新版本API及唯一worker。不要让两台机器或两个不同代码版本同时跑worker。正常取消需等待worker确认进程退出；隔离槽不得强制清空，需要原机器核查与受控恢复。API启动不自动改表。

该命令只新增三张索引/审计表：`analysis_workflow_model`、`analysis_workflow_result`、`analysis_workflow_publication`，不删除行情、特征或旧任务。旧任务表与鉴权表必须已完成各自显式迁移。

`TRAINING_ARTIFACT_ROOT` 默认 `StockAnalysisSystem/.runtime/training_tasks/candidates`；`TRAINING_CALENDAR_FILE` 默认 `.runtime/training_tasks/calendar.json`。相对路径均相对系统根目录解析，不依赖开发者盘符。磁盘矩阵在产物根相邻的 `workflow_work` 中，是可再生成的训练输入，不属于模型封存清单。API和worker必须共享配置、代码、数据库、日历与产物盘，并给独立输出预留空间；不可覆盖历史冻结模型。

远程访问沿用现有HTTPS反向代理、同源会话和CSRF，数据库/API内部端口不直接公开。Vite开发代理把新管理接口及published-results只读接口发往8084；发布读取不走mock。未运行worker时任务停留QUEUED，不伪造成功。

## API与版本

- `GET /api/admin/workflows/capabilities`：来源边界、默认Transformer池、资源和槽状态。
- `GET/POST /api/admin/workflows/jobs`：共享队列；POST必须带 `Idempotency-Key` 和CSRF，`kind=model_workflow`，操作 `train/predict/backtest/import`。详情/事件/取消复用 `/api/admin/training/jobs/{id}`。
- `GET /api/admin/workflows/models`：已保存模型；`GET /api/admin/workflows/results` 与 `/{id}`：管理员草稿预览。
- `POST /api/admin/workflows/results/{id}/publish` 或 `/withdraw`：当前管理员审核，记录操作者、时间和版本；无收益阈值。
- `GET /api/analysis/published-results` 与 `/{id}`：登录用户只读已发布版本；草稿或撤回版本404。

列表 `limit` ≤20、`before` 为服务端返回游标；明细 `section=scores/equity/trades/orders/writeoffs/requirements`，`limit` ≤100、`after` 为服务端返回的行游标，可选沪深 `ts_code`。scores读取worker已保存的最新日排行，不在请求时重算；所有分区先核对完整封存哈希。页面曲线仅代表当前分页，不隐藏未加载区间。接口响应不包含服务器路径和原始异常。

导入只接收已成功旧工程任务的32位ID，或已封存验证实验ID加固定trial：`raw_rmse20/raw_rmse300/raw_rankic300/csrank_rankic300`（LightGBM）。旧研究分支无需qualified为真；必须通过实际父候选/探针/模型绑定校验。禁止传文件路径、上传pickle或任意Python配置。

新导入会读取原候选绑定的特征版本，校验来源、算法、冻结股票池和逐股原始数据摘要，并在新模型中封存训练截止日的历史前缀。这样后续只追加数据时可复用保存模型预测，无需重训；历史被修改、原版本丢失或校验失败则拒绝导入。旧模型和旧封存不被覆盖，已经存在但没有前缀证明的导入模型不会自动获得新证据，需显式重新导入原候选。全市场导入逐股流式验证，会报告进度，但不加载全市场训练矩阵或执行训练。

## 运行与交付边界

### 用户选择指数与行业

用户页“选择股票池，查看模型预测”支持模型固定池、指数、行业与当前沪深A股全市场。行业列表直接读取 `stock_basic.industry`，不维护第二份硬编码分类；指数仅使用 `stock_constituent` 中已有的完整沪深300或中证1000成分快照。没有本地完整成分时不冒充全市场、不自动请求数据源。

目录同时提供已有不可变股票池版本和本地当前分类的内容寻址版本。浏览和提交用户预测均不新增股票池注册记录；提交时重新解析完整成员，分类已变化且未封存的旧版本会拒绝，提示刷新。既有保存版本仍保留原成员。行业是当前分类，不是历史逐日行业；指数展示实际成分快照日期，不能把请求日期当成分日期。

页面可搜索行业名称，展示所选池完整数量、版本及来源日期，并明确列出模型冻结数量和不兼容原因。仅当所选池全部成员都在已上线模型范围内才允许预测：例如当前主表新增股票时，旧模型固定池不等于当前全市场，不取两者交集悄悄缩池。不同模型仍各自遵循冻结成员和分数量纲。指数/行业结果是对该模型原始冻结池分数的筛选，不是针对行业重新训练或重新计算横截面特征；原模型排名保持不变。

用户请求继续复用精确匹配的封存预测或共享后台任务；没有匹配结果才排队预测，不训练、不补造缺失分数，也不给普通用户采集或发布权限。需要补齐来源、增加模型覆盖或保存管理员训练用股票池时，仍由管理员在对应后台入口操作。

### 缺失分数与逐股资格说明

用户预测结果的“股票池分数覆盖”展示完整所选池、有分数及无分数数量，并按股票代码分页列出缺失原因。`GET /api/analysis/user-predictions/{id}/coverage?limit=20&after=0` 与分数接口使用相同的当前账户授权、模型上线批准、缓存绑定、信号日期及完整封存校验；其他用户不能猜编号读取。`limit` 最大100，`after` 最大10000，只读取结果，不触发计算。

原因只取该封存包 `eligibility.json` 中覆盖信号日期的逐股 `excluded_ranges`：停牌、特征预热、上市前、退出上市有效期、原股票代码有效期之外。只给出计数、没有日期区间的旧产物，或未封存逐股原因的缺失项，统一显示“待核实”；不根据今天主表、当天无行情或其他股票的统计推断原因。统计和明细只针对用户选定的固定成员，不因分页缩小分母；原模型分数及排名不改变。

缺失原因文件被修改、与封存不符或与已有分数矛盾时拒绝明细，不伪造说明。页面保留已经读取的分数，单独提示明细错误并允许重试；选择其他股票池、模型、退出或切换账户会清除旧明细并中断旧请求。

固定全市场池允许包含训练截止日之后才有行情的股票：其截止日前历史以空前缀哈希封存，仍保留在股票编号映射中；样本资格由上市生命周期、实际行情和交易日证据逐日决定，不伪造历史、不静默删股票。后续预测仍核对原训练截止日前缀，新增上市后的行情不会被误判为修改旧历史。

保存的 LightGBM 预测和回测使用模型封存的固定成员及编号：主表新增股票、后续特征版本扩容，不会擅自扩大旧模型的池。每个旧成员仍必须存在于主表和可用特征版本中，缺失则明确拒绝，不能取交集缩池。新上市股票保留在数据库中，需有覆盖它们的新模型才能选择；新全市场训练仍要求当期主表与特征池完整一致，不借此跳过数据准备。

代码回归中的小样原生训练不等于已在正式数据库执行全市场训练，也不等于真实管理员已经发布结果。上线验收应由正常管理员登录提交小任务，逐个确认训练、重加载、预测、回测完成或缺口说明、预览、显式发布与撤回；不能伪造生产会话。

新训练数据、测试、规划、模型、缓存、日志和密钥不入GitHub；仅提交业务实现与本文档。正式结果与模型需要单独的持久化磁盘备份。
