# V0.3 Kafka Message Schema

## 1. 协议范围

V0.3 使用以下 Kafka Topic：

| Topic | Kafka Key | Value |
|---|---|---|
| `stock.ods.daily.v1` | `tsCode` | `StockDailyEvent` JSON |
| `stock.ods.basic.v1` | `tsCode` | `StockBasicEvent` JSON |
| `stock.dead-letter.v1` | 原消息 Key | 处理失败的原始消息 |

当前协议版本固定为：

```text
schemaVersion = 1
```

JSON 字段统一使用 `camelCase`。

## 2. StockDailyEvent

| `eventId` | `str` | `String` | 是 | 业务唯一标识 |

| `low` | `Decimal` | `BigDecimal` | 是 | 最低价 |
| `close` | `Decimal` | `BigDecimal` | 是 | 收盘价 |
| `preClose` | `Decimal` | `BigDecimal` | 是 | 前收盘价 |

## 3. eventId 规则

日线事件格式：

```text
{SOURCE}:{tsCode}:{tradeDate}
```

示例：

```text
TUSHARE:000001.SZ:20260703
```

要求：

1. `source` 使用大写。
2. `tradeDate` 在 `eventId` 中使用 `yyyyMMdd`。
3. 相同数据源、股票代码和交易日期必须生成相同的 `eventId`。
4. 禁止使用随机 UUID。
5. `eventId` 用于下游业务去重。

---

## 4. traceId 规则

单日采集任务格式：

```text
daily-{source}-{businessDate}-{taskId}
```

示例：

```text
daily-tushare-20260703-10001
```

同一次单日采集产生的所有事件必须使用同一个 `traceId`。

历史回补时，每个交易日独立生成一个 `traceId`。

---

## 5. Kafka Key

日线和股票基础信息 Topic 的 Kafka Key 必须使用：

```text
tsCode
```

示例：

```text
000001.SZ
```

Java Consumer 必须验证：

```text
Kafka Key == event.tsCode
```

禁止使用 `eventId`、`traceId` 或随机 UUID 作为 Kafka Key。

这样可以保证同一只股票的消息进入同一个 Kafka Partition。

---

## 6. 日期和时间格式

### tradeDate

格式：

```text
yyyy-MM-dd
```

示例：

```text
2026-07-03
```

Java 使用：

```java
LocalDate
```

### eventTime 和 ingestTime

格式必须符合 ISO 8601，并包含时区偏移：

```text
yyyy-MM-dd'T'HH:mm:ssXXX
```

示例：

```text
2026-07-03T15:00:00+08:00
```

统一使用：

```text
Asia/Shanghai
```

Java 使用：

```java
OffsetDateTime
```

禁止发送不带时区的时间。

---

## 7. 数值格式

Python 内部价格和金额使用：

```text
Decimal
```

Java 使用：

```text
BigDecimal
```

JSON 中发送数字，不发送带单位的字符串。

正确：

```json
{
  "close": 10.55,
  "volume": 1250345.00
}
```

错误：

```json
{
  "close": "10.55元",
  "volume": "125万"
}
```

---

## 8. source 取值

V0.3 支持：

```text
TUSHARE
AKSHARE
```

序列化后的值统一使用大写。

## 9. Java Consumer 校验规则

Java Consumer 必须检查：

1. `eventId` 不为空。
2. `traceId` 不为空。
3. `tsCode` 不为空。
4. `tradeDate` 不为空。
5. `source` 不为空。
6. `eventTime` 不为空。
7. `ingestTime` 不为空。
8. `schemaVersion == 1`。
9. Kafka Key 等于 `tsCode`。
10. `close >= 0`。
11. `volume >= 0`。
12. `amount >= 0`。

校验失败时：

1. 增加失败统计。
2. 记录 Topic、Partition、Offset 和 Kafka Key。
3. 不得导致 Consumer 进程退出。
4. 继续处理后续消息。

---

## 10. 协议兼容规则

V0.3 使用 `schemaVersion=1`。

兼容性规则：

1. 已发布字段不得随意改名。
2. 已发布字段不得随意改变类型。
3. 新增可选字段可以继续使用版本 `1`。
4. 删除字段或修改字段含义必须升级协议版本。
5. Java 遇到不支持的版本时必须拒绝处理并记录失败。
6. Python 和 Java 必须使用同一份 JSON 样例进行测试。

---

## 11. V0.3 职责边界

Python 负责：

```text
采集数据
生成事件
JSON 序列化
发送 Kafka
记录发送结果
```

Java 负责：

```text
消费 Kafka
JSON 反序列化
协议校验
异常隔离
消费统计
```

V0.3 Java Consumer 不负责：

```text
写入 MySQL
写入 ClickHouse
计算技术指标
行情清洗
状态去重
```
