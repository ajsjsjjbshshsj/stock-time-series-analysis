# V0.3 Kafka 消息协议

V0.3 以 Kafka JSON 作为 Python 与 Java 的语言边界。字段统一使用 `camelCase`，当前协议版本为数字 `1`。

| Topic | Kafka Key | Value |
|---|---|---|
| `stock.ods.daily.v1` | `tsCode` | `StockDailyEvent` |
| `stock.ods.basic.v1` | `tsCode` | `StockBasicEvent` |
| `stock.dead-letter.v1` | 原消息 Key | 原消息 Value 与诊断 headers |

## StockDailyEvent

| 字段 | Python | Java | 必填 |
|---|---|---|---|
| `eventId` | `str` | `String` | 是 |
| `traceId` | `str` | `String` | 是 |
| `tsCode` | `str` | `String` | 是 |
| `tradeDate` | `date` | `LocalDate` | 是 |
| `open/high/low/close/preClose` | `Decimal` | `BigDecimal` | 是 |
| `change/pctChg` | `Decimal` | `BigDecimal` | 否 |
| `volume/amount` | `Decimal` | `BigDecimal` | 是 |
| `source` | `str` | `String` | 是 |
| `eventTime/ingestTime` | `datetime` | `OffsetDateTime` | 是 |
| `schemaVersion` | `int` | `Integer` | 是 |

标准样例：[stock_daily_event_v1.json](examples/stock_daily_event_v1.json)。日线 `eventId` 固定为 `{SOURCE}:{tsCode}:{tradeDate-yyyyMMdd}`，相同业务数据必须重复生成相同 ID。

## StockBasicEvent

| 字段 | Python | Java | 必填 | 说明 |
|---|---|---|---|---|
| `eventId` | `str` | `String` | 是 | `{SOURCE}:{tsCode}:BASIC` |
| `traceId` | `str` | `String` | 是 | 一次基础信息采集任务标识 |
| `tsCode` | `str` | `String` | 是 | Tushare 股票代码 |
| `symbol` | `str` | `String` | 是 | 简称代码 |
| `name` | `str` | `String` | 是 | 股票名称 |
| `area` | `str` | `String` | 否 | 地区 |
| `industry` | `str` | `String` | 否 | 行业 |
| `listDate` | `date` | `LocalDate` | 否 | 上市日期 |
| `source` | `str` | `String` | 是 | `TUSHARE` 或 `AKSHARE` |
| `eventTime` | `datetime` | `OffsetDateTime` | 是 | 数据业务时间 |
| `ingestTime` | `datetime` | `OffsetDateTime` | 是 | 事件生成时间 |
| `schemaVersion` | `int` | `Integer` | 是 | 当前为 `1` |

标准样例：[stock_basic_event_v1.json](examples/stock_basic_event_v1.json)。V0.3 已提供 Java 公共契约；现有 Python V0.2 基础信息命令仍直接写 MySQL，因此基础信息 Topic 的真实生产与消费暂记为 `NOT_EXERCISED`。

## 格式与校验

- 日期使用 `yyyy-MM-dd`。
- 时间使用带时区偏移的 ISO 8601，例如 `2026-08-14T09:00:00+08:00`。
- 价格、数量和金额发送 JSON 数字，Python 使用 `Decimal`，Java 使用 `BigDecimal`。
- Java 必须检查 Kafka Key 等于 `event.tsCode`。
- `schemaVersion` 由 `STOCK_SUPPORTED_SCHEMA_VERSION` 配置，默认只接受 `1`。
- 不支持的版本、JSON 解析失败和字段校验失败均发送到 DLT；只有 DLT 发布成功后才确认原消息。

DLT 保留原 Key/Value，并增加 `x-original-topic`、`x-original-partition`、`x-original-offset`、`x-error-type`、`x-error-message` headers。
