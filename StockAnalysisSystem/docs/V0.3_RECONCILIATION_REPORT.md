## 真实 dual 批次

状态：`NOT_EXERCISED`。

阻塞条件：现有 Compose 不包含 MySQL 服务，本轮也没有获得一个可安全使用的真实 Tushare/MySQL 受控批次，因此无法形成同一 `traceId` 下的 Collector → MySQL/Kafka → Java 对账。没有读取或打印任何 Token、数据库密码。

环境就绪后，先运行一次 `COLLECTOR_OUTPUT_MODE=dual` 的受控批次，记录 Collector 行数、MySQL 成功数、Kafka callback 成功/失败、Java 成功/隔离增量和 DLT 增量，再执行：

```powershell
D:\Python\python.exe scripts\reconcile_v03.py --real-collector --trace-id <traceId> --collector-count <n> --mysql-count <n> --kafka-success <n> --kafka-failure <n> --java-success <n> --java-isolated-failure <n> --dlt-count <n>
```

任一输出侧失败时脚本返回 `PARTIAL` 或 `FAIL`，不会用另一侧成功掩盖问题。

回滚模式：`COLLECTOR_OUTPUT_MODE=mysql`。
