# 固定股票池网页补缺

管理员在股票池管理页选择已保存版本和日期，点击“补齐当前固定池缺失数据”并确认，才会创建真实准备命令。预览、切换股票池、覆盖查询、任务列表和页面加载都不采集、不训练、不发布。普通用户不能读取或提交管理命令。

## 与原采集流程的关系

使用原缺失优先的`market-gap-v1`规划、来源封存、节流、每日任务、心跳与独占采集worker；没有另开一个HTTP采集器。固定池版本、完整成员顺序与日期绑定到批次，不跟随active或行业分类变动换股。

所选成员都必须有可信上市资料，不认识的股票不会被静默删除。上市前、退市后、代码独立有效期外不补造数据；固定池成员仍保留在批次身份内，区间适用成员单独计算。有证据的无报价/停牌与待核对缺口沿用现有规则。

固定池只规划对应股票的缺失键，使用按股区间请求；不能因为小池的所有数据缺失就请求整日全市场行情。原未指定股票池的夜间全市场优化保持不变。已有价格不重复回查或覆盖，也不以行数一致作为合法性条件。

## 明确的就绪层次

| 状态 | 含义 |
| --- | --- |
| NOT_STARTED | 准备命令尚待worker规划 |
| RUNNING | 日任务仍在排队、运行或等待额度 |
| READY_CORE | 预期日任务全部存在且成功；核心行情补缺完成 |
| NO_APPLICABLE_SESSIONS | 固定成员在该区间没有适用交易日 |
| NEEDS_CHECK | 存在失败或部分完成的日任务 |
| FAILED | 规划失败，需要检查错误并显式重试 |

所有返回都保留`model_ready=false`。READY_CORE不是价格数值复核、因子完整、特征发布、模型样本就绪或训练完成。后续模型必须独立执行相应校验；没有适用样本不能直接训练。

预期日任务数量与批次一同固定。缺少任务关系或日记录时返回依赖错误，不能误报完成或零缺口。规划中断后复用已保存批次和日期任务，不重新按变化后的数据库扩池或改计划。

## 运维与重试

新版本新增两张命令/关系表`market_pool_preparation_request`和`market_pool_preparation_day`，不复制价格表。需要先显式迁移；HTTP和worker不会自动建表。已有项目基础SQL迁移仍须先完成。

在python-collector目录执行（每条为单行）：

```text
python scripts/prepare_stock_pool_data.py web-migrate
python scripts/prepare_stock_pool_data.py worker --nightly --nightly-at 20:00
```

第二条会真实启动采集及夜间调度，只应由运维明确执行；不要在两台机器同时运行worker。准备命令入队不会自动启动worker，worker停止时保持排队。既有未迁移环境的夜间worker会跳过可选新收件箱，不自行建表。

“重试准备规划”只重试原准备命令，保留固定池、日期和已有批次；已提交的规划不会被重置。失败/部分完成的当日任务通过“重试当日任务”进入原有持久化重试收件箱，只作用于关联的原日任务和原批次。未关联的日任务不可通过该路径重试。

沿用现有限流等待策略；存储、来源校验或耗尽底层重试的网络故障不会被伪装成成功。必须先解决故障，再显式重试。真实夜间持续运行验收与隔离故障测试是不同证据。

## REST

全部位于`/api/admin/preparation/requests`，受当前管理员会话保护，写操作校验Origin与CSRF。接口不接受任意命令、文件路径、数据行、actor或SQL。

| 方法/路径 | 内容 |
| --- | --- |
| POST / | `{pool_version,start,end}`，32位十六进制Idempotency-Key，202只表示入队 |
| GET / | `limit=1..50,offset=0..100000`，有界任务列表 |
| GET /{id} | 固定请求、真实子任务计数和核心数据状态 |
| GET /{id}/tasks | 同样分页的关联交易日任务 |
| POST /{id}/retry | 空JSON对象，幂等重试原规划 |
| POST /{id}/tasks/{task_id}/retry | 空JSON对象、Idempotency-Key，202表示原日任务重试入队 |

日期从2023-01-01起，上海时间严格大于16:00才允许请求当天；执行时使用可信交易日历，不按周一至周五猜交易日。请求日期在排队后保持不变，不因后来过了16:00而扩大到当天。
