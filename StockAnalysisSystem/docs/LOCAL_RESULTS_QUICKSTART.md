# 本机使用：登录、查看与发布真实结果

本页适用于已配置环境和已恢复数据库/产物的电脑。首次安装、迁移和完整备份先看 [可迁移安装与恢复](PORTABLE_SETUP.md)，算法与资源限制见 [三模型工作流](MODEL_WORKFLOWS.md)。GitHub 只包含源码，不附带真实数据库、模型、账号密码和本机 `.env`。

## 1. 启动与登录

使用已安装项目依赖的 Python 环境；`python`、`npm` 应指向本机配置的环境，不依赖开发者盘符。先启动 MySQL。下列命令从 `StockAnalysisSystem` 目录执行，每条分别在独立终端前台运行，关闭相应终端会停止服务；端口已被正确服务占用时不要重复启动。

```powershell
python scripts/manage_project.py start --service prediction
```

```powershell
python scripts/manage_project.py start --service frontend
```

另开终端，在 `StockAnalysisSystem/python-services/stock-analysis-app` 执行：

```powershell
python scripts/training_worker.py status
```

只有需要处理后台任务，且已确认无其他训练 worker、执行槽未隔离时才启动唯一 worker：

```powershell
python scripts/training_worker.py run
```

worker 会处理已排队任务；若本轮不希望计算，先核对队列，不要盲目启动。查看、发布和撤回已有封存结果不要求重新训练。行情/监控页面另需 Market API、Consumer 及相应基础设施，按各模块指南启动，不把模型结果服务健康等同于整个 Docker/Flink 链路健康。

主 `.env` 使用现有数据库配置和受保护模式：`AUTH_MODE=protected`，本机同源入口为 `AUTH_ORIGIN=http://127.0.0.1:5173`，仅本机测试允许 `AUTH_ALLOW_LOCAL_HTTP=true`，`AUTH_SECRET` 为自行生成且至少32字节的稳定随机密钥。API与管理命令必须使用相同配置；不得把密钥放到前端。不要交替使用 `localhost` 和 `127.0.0.1` 登录。

- 登录：`http://127.0.0.1:5173/#/login`。
- 管理员模型工作台：`http://127.0.0.1:5173/#/models`。
- 管理员账号管理：`http://127.0.0.1:5173/#/accounts`。
- 用户端：`http://127.0.0.1:5173/#/user`，选择“已发布模型结果”。

没有默认账号或默认密码，不提供公开注册。当前机器已有账号时直接登录，不要重复初始化。仅全新未初始化的认证库，在分析应用目录显式执行 `python scripts/manage_accounts.py migrate`，然后 `python scripts/manage_accounts.py bootstrap`，根据交互输入初始管理员账号密码。新用户由管理员在账号管理页创建；首次登录按提示改密。不要把密码放进命令参数、截图、日志或Git。

若页面登录返回404，核对Vite代理和8084是否运行当前版本；8084端口占用不代表应再启动第二个API。403时核对入口与`AUTH_ORIGIN`一致，再刷新登录；不要关闭CSRF或角色校验绕过问题。

## 2. 管理员：先选已有结果，不必重训

在模型工作台下方“预测与回测结果 · 审核发布”点击一条结果。任务`SUCCEEDED`、产物`COMPLETE`与“已发布”是不同状态：计算完成后仍默认未发布，普通用户看不到草稿。

预览时核对：

| 展示 | 含义 |
| --- | --- |
| 结果ID / 模型ID | 本条不可变结果版本及其实际使用的模型版本 |
| 信号范围 / 实际信号截止 | 请求区间及实际有评分的信号日期，不强行显示今天 |
| 数据源截止 | 当时封存绑定的数据源上限，不代表模型训练到该日，也不代表本次使用了所有源日期 |
| 模型已见数据 | 训练/验证期间已见数据边界，区别于信号和源数据日期 |
| 股票池 / 实际参与评分 | 固定池的范围与人数，以及本报告实际有评分的人数；二者可因上市、停牌等资格不同 |
| 量纲 / 持有周期 | 概率、排名分数和收益预测不可混称或直接横比 |

小池最多展示20只完整成员；全市场只展示范围、数量与封存来源提示，不在每页展开数千代码。旧报告没有记录的字段明确显示“未记录”。展示补充来自已核验封存元数据，不改写旧报告或重新推理。

预测分区显示最新信号，预测本身不生成虚构净值曲线。回测可查看权益、成交、未成交和执行假设；曲线只代表当前服务端分页，翻页查看后续记录。用户选择股票过滤时，空记录可能表示该股不在池中或此分区不适用，不自动补造信号。

负收益、低相关或未定义指标不等于功能失败，应如实呈现。`NOT_READY`表示缺执行证据，不能发布该回测；缺口清单可供核查。训练任务`TIME_LIMIT`表示保护性超时，不会生成一个“成功的新模型”。新全市场LightGBM尚未完成时不要用旧模型冒充，不需要为了打开页面而重新训练。

## 3. 发布、用户查看与撤回

1. 管理员阅读所选完整结果，确认日期、股票池、模型版本、量纲和研究限制后，点击“确认发布给用户”并确认弹窗。
2. 发布对象是这一条`result_id`，不是整个模型或全部历史结果；后续新结果仍需单独审核，不自动发布。
3. 用户登录`/#/user`，选择“已发布模型结果”并刷新发布列表，选择版本和分区。用户端只有读取，不具备训练、发布、撤回和配置修改能力。
4. 管理员选中已发布结果，点击“撤回发布”并确认。用户后续刷新或读取该结果不再可见；已下载到浏览器的数据无法远程抹除。

发布与撤回均校验当前管理员角色和CSRF，并写审计。完整性校验异常时拒绝读取，不降级为mock结果。不保证研究结果盈利，不应将历史工程小训练标为正式全市场模型。

## 4. 日常检查与停机

- API健康：访问 `http://127.0.0.1:8084/health`，同时检查`status`与`database`，不能只看端口。
- 未登录受保护接口应拒绝；用户不可通过修改前端路由获得管理员权限。
- worker运行期间不要启动第二个，也不要让两台机器同时处理同一执行槽。
- 取消使用页面“取消任务”，等待服务端最终状态。隔离槽按受控CLI恢复，先核查原worker与子进程，不直接改数据库清空槽。
- 停止前台服务用对应终端Ctrl+C；不要靠关闭网页停止训练。后台常驻方式因操作系统而异，应由已配置服务管理器管理，不使用固定盘符的私人脚本作为跨机前提。
- 备份数据库、模型封存目录和运行来源；源码同步不能代替数据备份。不要删除旧封存模型、来源、回执或断点来“清理代码”。
