# V0.4 发布说明：统一市场数据入口

## 主要变化

- Tushare/AkShare SDK 访问全部收口到 `python-services/python-collector`。
- 新增 `stock_daily_basic`，保存原始换手率、估值和总市值。
- 新增 `stock_constituent`，保存指数/行业成分股历史快照。
- 新增 `daily-basic`、`daily-basic-history`、`constituent`、`daily-market` 命令。
- `stock-analysis-app` 的旧 `DataCollector` 保留方法签名，但实现改为 MySQL 读取。
- 分析端行情查询通过 LEFT JOIN 返回旧 OHLCV 字段和新增 daily-basic 字段。
- 行业/指数筛选改读数据库最新成分股快照。
- 删除分析端 Tushare/AkShare 封装和依赖。
- 保留 `raw_panel.parquet`、`panel_features.parquet`、`features_*.parquet`、模型文件和 Streamlit 缓存路径。
- V0.4 新表显式使用 `utf8mb4_general_ci`，兼容旧 `stock_daily.ts_code`，迁移脚本也会修正已按 MySQL 8 默认排序规则创建的存量新表。

## 运行方式

先采集，再分析：

```powershell
cd python-services\python-collector
python -m app.main daily-market --date 20260817
python -m app.main daily-basic-history --start 20220104 --end 20260817
python -m app.main constituent --type index --code 000300.SH --date 20260817
```

分析命令继续使用原入口；`--use_tushare` 仅为兼容旧脚本，已不选择分析端数据源。

## 回滚

- Kafka 不可用：设置 `COLLECTOR_OUTPUT_MODE=mysql` 并重启 Collector。
- daily-basic 不可用：OHLCV `daily` 任务仍可独立成功；分析端 LEFT JOIN 保留行情行，新增字段为 NULL。
- 历史 daily-basic 未补齐：分析端仅对数据库空值临时读取旧 `raw_panel.parquet` 的换手率，不覆盖数据库非空值。
- 代码回滚不删除 `stock_daily_basic`、`stock_constituent`；它们与旧分析表互不冲突。

## 已知限制

- Tushare 不提供当前设计中的行业成分股接口，行业快照主要由 AkShare 采集。
- `kafka` 单输出模式只保证既有 OHLCV 消息；完整分析数据仍要求 `mysql` 或 `dual`。
- Docker/Kafka 不运行时，可用 `mysql` 模式完成数据库采集，Kafka 链路需另行启动后验收。
