# V0.7 单股真实 XGBoost 预测

V0.7 在 V0.6 真实行情概览旁接入预测标签页。数据从 MySQL 读取，训练及发布只能由显式离线命令执行；Python 只读 API（8084）和浏览器 GET 不训练、不发布、不自动建表。旧 `main.py`、LightGBM/Transformer、模型登记及 Parquet 缓存保持原路径和行为。

## 口径与限制

目标契约为 `next_trading_day_close_return`，`horizon=1`，公式 `close[t+1] / close[t] - 1`。API 保存小数收益率，例如 `0.01` 表示 `1%`，页面仅转换一次。RMSE/MAE 在 API 同为小数收益率，页面是百分点；R² 无单位、未定义时为 null，不是概率。零收益基线在同一完整测试序列上计算，不承诺模型优于基线，也不构成投资建议。

读取的是原始未复权收盘价，除权、除息和公司行动可能造成跳变；不是分红复权或经济总收益。`daily_basic` 可能被供应商追溯修订，不能据此保证历史时点可获得性（point-in-time）。历史缺失日也会使相邻数据库行不等于相邻交易日：必须在采用 horizon=1 结论前另行审计权威交易日历和行情完整性；不能仅凭周末规则或按日期加一天推定下一交易日。

初次本地对账使用 `000001.SZ`，1066 条 MySQL 历史记录，范围 `2022-01-04..2026-08-17`，213 条冻结测试记录。源记录存在 `2026-05-29→2026-08-14` 的 77 个日历日间隔，因此这次对账只证明“下一条已存观测”的标签及指标一致，**不证明真实下一交易日 horizon=1**。系统日期为 2026-10-03 不会自动让模型或数据库截止日更新。补齐行情后须另行显式训练、发布及重新验收，不能复用旧模型评估冒充新验收。

用户随后授权补齐 `000001.SZ`，原有 1066 条保留，新增 84 条，源数据共 1150 条，最新权威开市日为 `2026-09-30`。新模型与交易日连续性门禁正在另行验收；下列旧 ID/8 月范围仅为可追溯历史示例，不是补齐后最终有效模型。补齐后的源数据应使旧缺口模型的严格逐日对账失败，这是正确的拒绝，不应绕过。

## 配置与权限

使用已安装应用依赖，数据库参数由私有 `.env` 或环境变量 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` 提供。应用优先读取自身 `.env`，否则读取 `StockAnalysisSystem/.env`。不要提交、输出或把密码放入浏览器配置和命令行。以下示例均在仓库根目录的 PowerShell 中执行，每条命令单行；安装位置不同可替换 Python 路径。

数据库结构由管理员预先准备，本功能不运行 DDL 或 `create_all`。离线训练/推理发布账号只需源表 SELECT 和 `analysis_result` INSERT；API 账号仅需 `stock_basic`、`analysis_result` SELECT；对账账号仅需 `stock_daily` SELECT。不同进程用不同环境配置/账号启动，切勿因示例统一变量名就给 API 或对账器写权限。查询均有参数绑定、条数和连接/读取超时。

## 显式训练与加载模型推理

训练必须传带后缀股票代码及 ISO 起止日期。历史上限 2500 行、最少 300 条有效历史，非法 OHLC、重复日期及不足历史明确失败；缺失可选估值可使用 XGBoost 原生 NaN。CPU、随机种子 42、有界参数；固定 `v07_fixed_1` 特征顺序不含未来标签。约 60/20/20 时间切分；训练标签结束日不进入验证区间，验证标签结束日不进入测试区间。已见边界包含训练和验证，测试不能用于拟合、调参或早停。

在单独终端设置应用工作目录：

```powershell
Set-Location F:/java-stock-analysis/stock-time-series-analysis/StockAnalysisSystem/python-services/stock-analysis-app
D:/Python/python.exe -m scripts.forecast train --stock 000001.SZ --start 2022-01-04 --end 2026-08-17
```

使用命令输出的 `model_id`。以下 ID 是初次历史验收示例，并非当前模型的通用别名；推理命令加载既有冻结模型，**不会重新训练**，但会向结果表新增一条发布记录：

```powershell
D:/Python/python.exe -m scripts.forecast predict --stock 000001.SZ --start 2022-01-04 --end 2026-08-17 --model v07_ef4385877b634871b56afd8db6d8921e
```

测试与 latest 使用同一冻结模型，不在评估后重训。latest 来自真正最后一条行情且必须晚于模型已见边界，不需要真实 y；`actual_return=null`、`target_date=null`，页面标为“下一交易日”。它是截至数据截止日的历史预测，不是今天、实时或未来五天预测。后续推理可更新 latest/cutoff，但不改变冻结测试、指标、原始训练摘要和已见边界。

模型以 XGBoost 原生 JSON 与元信息存入受控 `models/v07/{model_id}`，不加载外部 pickle、不接受用户上传或请求文件路径。须信任本地模型存储并限制写权限。先原子完成模型文件，再事务性追加完整结果；失败不暴露半成品，旧记录不删除。重新训练生成新的不可变 ID，加载推理可产生同一 ID 的多个发布记录，`publication_id` 区分这些发布。模型输出被 Git 忽略；勿提交模型、`.env`、构建目录或依赖。

## 只读 API 与页面

在应用目录，用只读数据库账号启动：

```powershell
D:/Python/python.exe -m uvicorn api.forecast:app --host 127.0.0.1 --port 8084
```

在另一终端只读查询，完整对账要 `limit=500`（默认仅尾部 60 行，不能拿局部序列验算全测试指标）：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/models?ts_code=000001.SZ'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/prediction/000001.SZ?model=v07_ef4385877b634871b56afd8db6d8921e&limit=500'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/models/v07_ef4385877b634871b56afd8db6d8921e/importance?top=15'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/results/000001.SZ'
```

`/models` 返回元信息数组，默认 20、最多 100；`/prediction` 返回 `{metadata,test_series,latest}`，序列最多 500；元信息有意不含重要性，重要性走专门端点（gain，top 1..100）。`/results` 是发布摘要数组，不是旧分析 JSON。非法输入 400、未知或跨股票模型 404、依赖故障脱敏 503，已知股票无模型是 200 空数组；无结果提示离线准备，不回退模拟数据。没有网页训练 POST。

回到仓库根目录启动前端：

```powershell
Set-Location F:/java-stock-analysis/stock-time-series-analysis/StockAnalysisSystem/frontend
npm.cmd run dev -- --host 127.0.0.1
```

选择“接入现有 API”，分析页可用真实概览及预测；其他未接入标签仍禁用，演示模式原功能保留。预测展示模型/切分/截止日、测试曲线、零基线和独立未知实际值卡片，不画概率、混淆矩阵或虚构未来价格。切换股票/模型会取消请求并拒绝过期响应。真实错误不触发演示回退。默认 `FORECAST_API_TARGET=http://127.0.0.1:8084` 只代理明确预测路径，行情仍去 8083，监控仍去 8080；生产需配置同源反向代理，不应把整个 `/api/analysis` 指向 Python，也不能把数据库凭据放入 Vite。

## 独立只读对账

在仓库根目录运行（仅 SELECT、HTTP GET、读取受控元信息，不加载模型，不训练、不发布、不写缓存）：

```powershell
D:/Python/python.exe StockAnalysisSystem/scripts/verify_v07_prediction.py --stock 000001.SZ --model v07_ef4385877b634871b56afd8db6d8921e --start 2022-01-04 --end 2026-08-17 --api-base http://127.0.0.1:8084
```

退出 0 只表示明确范围的存储观测对账 PASS。逐条用独立 Decimal 收盘比值验算实际收益，独立计算完整测试 RMSE/MAE/R² 和零基线；检查模型/股票绑定、严格日期顺序、切分与原始已见边界、最新未知实际值及冻结元信息一致性。JSON 数值容差为 `abs 1e-10 + rel 1e-8 × abs(expected)`，单位为小数收益率；不允许 NaN/Infinity、重复 JSON 键或不完整尾部样本静默跳过。

输出源记录数/起止日、checked/test 数、原始已见边界及超过 7 个日历日的观测间隔（其中可能包括合法节假日）。`training_label_provenance_verified=false`：没有独立重建训练特征/标签。`exchange_calendar_completeness_verified=false`：没有权威日历对账。PASS 不能消除源数据缺口、公司行动、point-in-time 或投资风险。失败退出 1 并脱敏，不打印数据库错误/密码。无需重放 Kafka、清空 MySQL、删除缓存、重建集群或检查点。
