# 用户选池与模型预测

用户端 `/#/user` 顶部提供“股票池 → 已上线模型 → 开始预测”。相同条件读取已有完整结果或复用同一后台任务；没有才排队预测，完成后直接向有权请求的用户展示，不需要逐条结果审核。

## 权限与上线

管理员在模型工作台审核“上线供用户预测”。只接受已保存、完整性核验通过的固定模型版本；没有默认上线模型。撤下后新请求、既有结果读取和尚未执行的授权检查均拒绝。重新上线建立新的审批版本，旧授权不自动复活。

普通用户只能提交模型编号和固定股票池版本；不能提交文件路径、SQL、日期、训练参数、任务种类，不能调用训练、采集或发布接口。用户预测不提升账号角色。队列由审核管理员作为受限执行责任人，复用原单槽 worker、资源限制、租约、取消和隔离机制。普通用户没有共享任务取消权。

这是对旧“客户端完全不触发计算”的明确调整：**只允许已审核保存模型的推理，不允许训练**。历史 Transformer 封存包和原结果审核/发布流程保持不变；预测结果也不会自动进入原公开发布列表。

## 股票池与日期

默认支持模型原冻结池；管理员已保存的指数、行业或全市场版本，只有全部成员都在模型支持范围内才可选，不偷偷取交集。模型仍按完整冻结池和原映射运行，再按用户所选池筛选展示分数；原模型排名不重新归一化。停牌、上市时间和指标预热可能使成员没有合格分数，不补造。

20只试点 Transformer 不能直接支持沪深300或全市场；须先由管理员训练、验收并上线兼容模型。股票池列表最多展示最近50个已保存版本，模型上线最多20个。

预测使用“最新已完成交易日”与“当前可用特征版本截止日”的较早者，界面明确显示实际信号日期与数据截止日；不声称历史缓存是当日结果。不在用户HTTP请求内采集、重建特征、训练或加载原生模型。没有该日期完整分数时显示未就绪，不能冒充最新成功。

## 缓存与访问隔离

缓存身份包括模型封存摘要、审批版本、股票池版本及成员、固定推理请求、完整来源/特征/代码/依赖绑定摘要。输入变化产生新身份，不覆盖旧封存。相同请求跨用户复用一次计算，但每位用户必须显式请求获得授权；猜测其他请求编号无法读取私有结果。

若同一负责管理员的后台／夜间预测已经排队或运行，且模型、标准化请求和完整输入绑定都一致，用户请求会共用它，不再创建第二次计算；不同输入或其他负责管理员的任务不会误复用。极小的并发入队竞争会返回409要求显式重试，而不是留下重复任务。事务内核验复用现有数据库连接，避免连接池耗尽时相互等待。

全新计算最多每用户2个未完成、全局20个未完成；重复命中不会产生新计算。失败、中断、取消不会在重复点击时偷偷无限重试。队列与缓存授权同一事务提交，避免任务先运行、授权后补的竞态。已有管理员预测也只有全部输入绑定和日期完全匹配、封存完整时才能复用。

## 初始化与运行

先完成已有账户、队列、工作流和市场数据迁移，停止训练 worker，确认执行槽空闲。在 `python-services/stock-analysis-app` 运行单行命令：

```powershell
python scripts/training_worker.py migrate-predictions
```

只创建四张控制表：`analysis_prediction_model`、`analysis_prediction_model_audit`、`analysis_user_prediction`、`analysis_user_prediction_access`，不会上线模型或启动计算。API重启加载新路由后，管理员显式审核模型，再按原文档启动唯一训练 worker。没有 worker 时任务会显示排队，不假报开始运行。不要同时在两台机器启动同一队列 worker。

## 验收边界

隔离合成分数和测试队列证明功能、授权、复用和展示，不代表新模型的收益、全市场资源消耗或服务器部署已验收。模型上线是管理员的明确操作，不由代码部署或自动化测试代替。
