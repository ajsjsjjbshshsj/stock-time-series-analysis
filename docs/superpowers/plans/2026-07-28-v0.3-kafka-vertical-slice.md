# V0.3 Kafka Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify the first runnable `Python → Kafka → Java` stock-event path without changing the V0.2 MySQL collection jobs.

**Architecture:** `StockAnalysisSystem` becomes the integration root. A Python smoke producer emits deterministic `StockDailyEvent` V1 JSON to a KRaft Kafka broker; a Java 21 multi-module Spring Boot service deserializes, validates, isolates invalid messages, publishes them to a DLQ on a best-effort basis, and exposes statistics and recent errors.

**Tech Stack:** Python 3, `confluent-kafka`, `simplejson`, pytest, Docker Compose, Apache Kafka KRaft, Kafka UI, Java 21, Maven 3.9+, Spring Boot 4.1.0, Spring for Apache Kafka, Jackson, JUnit 5, Mockito.

## Global Constraints

- Preserve all V0.2 Collector, Job, Repository, MySQL configuration, and behavior.
- Do not modify `DailyCollectionJob`, `HistoryBackfillJob`, or `RetryFailedJob` in this plan.
- Do not implement `mysql|kafka|dual`, `collection_delivery`, or `PARTIAL_SUCCESS` yet.
- Do not introduce Flink, ClickHouse, Redis, Spark, Iceberg, MinIO, or Airflow.
- Java version is 21.
- Kafka JSON uses camelCase, UTF-8, `schemaVersion=1`, and Kafka Key equal to `tsCode`.
- `eventId` is deterministic: `{SOURCE}:{tsCode}:{yyyyMMdd}`.
- Event timestamps use an explicit `+08:00` offset for Asia/Shanghai.
- Never write real Tushare tokens, database passwords, or Kafka credentials to tracked files or logs.
- The current checkout resolves to the unrelated Git root `F:/`. Do not run `git add` or `git commit` until the user establishes a safe repository boundary for `StockAnalysisSystem`; each task therefore ends with a verification checkpoint instead of a commit.

- [ ] **Step 3: Implement consumer flow**

```java
@KafkaListener(topics = "${stock.kafka.daily-topic}")
public void consume(ConsumerRecord<String, String> record, Acknowledgment acknowledgment) {
    statistics.recordConsumed();
    try {
        StockDailyEvent event = objectMapper.readValue(record.value(), StockDailyEvent.class);
        validator.validate(record.key(), event);
        statistics.recordDailySuccess();
    } catch (UnsupportedSchemaVersionException ex) {
        isolate(record, "UNSUPPORTED_SCHEMA", ex);
        statistics.recordUnsupportedSchemaFailure();
    } catch (JsonProcessingException ex) {
        isolate(record, "JSON_PARSE", ex);
        statistics.recordJsonFailure();
    } catch (EventValidationException ex) {
        isolate(record, "VALIDATION", ex);
        statistics.recordValidationFailure();
    } finally {
        acknowledgment.acknowledge();
    }
}
```

Each failure method must increment total failure exactly once; tests must catch double counting.
